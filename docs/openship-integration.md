# Интерфейс GMan в OpenShip

В соседнем репозитории `../openship` добавлен раздел `/infrastructure` и пункт меню
«Инфраструктура». Страница показывает каталог GMan, все обнаруженные экземпляры,
серверы, метрики CPU/RAM, конфигурацию JSON и ссылки на Grafana за последний час.
Карточка экземпляра доступна по URL с hash; данные обновляются каждые 30 секунд.
Автор запуска показывается только при совпадении экземпляра и времени старта
с подтверждённым событием релиза в последних событиях GMan.

## Запуск

Сначала запустить GMan (создаёт Docker network `gman_default`), затем:

```sh
cd ../openship
docker compose -f docker-compose.yml -f docker-compose.gman.yml up -d --build dashboard
```

Dashboard: http://127.0.0.1:3001/infrastructure. Войти в существующую учётную запись
OpenShip, затем ввести `GMAN_READ_TOKEN` из `.env` GMan. Подходит и admin-токен,
но интеграция разрешает только чтение. При перезагрузке страницы токен вводится снова.

OpenShip хранит своё состояние отдельно; данные GMan не копируются в его базу.
Текущий портал GMan продолжает работать на http://127.0.0.1:8080.

## Доступ

`/api/gman/[...path]` проверяет сессию OpenShip и передаёт пользовательский Bearer
токен в GMan. Разрешены только `GET overview` и `GET metrics/current`. Общий
серверный токен не используется, права организаций OpenShip не подменяют права GMan.
Ответы не кэшируются. Токен остаётся в памяти страницы, не в URL или localStorage.
`GMAN_INTERNAL_URL=http://gman-api-1:8000` задаётся в Compose override. Для другой
инсталляции нужно изменить адрес и сетевое подключение.

Первый этап интеграции: просмотр. История всех релизов, редактирование каталога,
управление деплоем и единый SSO через этот раздел пока не реализованы. Grafana
требует собственного входа. При недоступности метрик конфигурации остаются доступны.
